# Changelog (developer)

This file follows the [Keep a Changelog](https://keepachangelog.com/) format. For versioning rules, see [versioning.md](versioning.md). The short, public changelog is [CHANGELOG.md](CHANGELOG.md).

This repo is the **client** (phone/tablet) side of Macro Grid and is versioned independently of the server (`https://github.com/Deccoyi/macro-grid`).

## [Unreleased]
### Added
- **Phone language:** `src/i18n/` holds `tr.ts` (defines `DictKey`) and `en.ts`; `t(key, ...args)` picks the dictionary once at start-up from `navigator.languages[0]` (Turkish when it starts with `tr`, English otherwise). `App.tsx`, `QrScan.tsx` and `SettingsPanel.tsx` no longer hard-code texts; the default device name sent in `hello` is translated too. Error texts that arrive from the server are English.
- **Third-party license compliance:** `THIRD_PARTY_NOTICES.md` is now a full index (name, version, SPDX license, copyright holder, URL, path) of the production npm packages and the resolved Android release runtime classpath, and `licenses/<library>/` holds the original license texts (Android library families share one canonical Apache-2.0 text). ML Kit and Google Play services are linked to their proprietary terms instead of copied. A small Vite plugin in `vite.config.ts` copies the notices and `licenses/` into `dist/`, so they are packaged into the APK with the web assets. No in-app screen yet: the settings UI has no i18n files (its strings are hard-coded), so a link there is left as a follow-up.
- **Release APK build (`docs/release.md`):** `scripts/build-release-apk.ps1` builds the web bundle, syncs Capacitor and runs `assembleRelease`, then copies the APK to `artifacts/`. `android/app/build.gradle` now takes `versionName` from `package.json` and derives `versionCode` (`major*10000 + minor*100 + patch`), and signs the release build from `android/keystore.properties` when that file exists (git-ignored, as are `*.jks` / `*.keystore`); without it the APK is produced unsigned. Verified with a throwaway keystore and `apksigner verify`. The real keystore has to be created by the owner and kept safe.
- **Dynamic icons and text:** `widget.state` may carry `style.icon` (an image URL or an empty string for no icon), applied through `liveStyle`; the renderer copy's types were extended. `widget.state` messages are now passed through the asset step too (`connection.ts`), so a dynamic icon that arrives as an `asset:` reference is resolved before it is applied.
- **`layout.patch` and cached assets** (`src/ws/layoutPatch.ts`, `src/ws/assets.ts`, `src/ws/connection.ts`; protocol described in the server repo's `docs/done/layout-patch-and-assets.md`). `hello` announces `capabilities: ["assets", "layout.patch"]`. Incoming messages are handled in arrival order; a layout that references uncached `asset:<hash>` values sends `asset.get` and waits (max 5 s) for the `asset` replies, which bypass the queue. `applyLayoutPatch` keeps the identity of every untouched page and widget, and `resolveAssetRefs` keeps the identity of every subtree without references, so React skips unchanged widgets. On a patch only the changed widgets lose their cached live state (`onLayoutPatch`). A patch that does not fit the held profile closes the socket so the reconnect brings a full layout. Assets are cached in memory and `localStorage` (LRU, 400 entries); the layout cache now stores the compact `asset:` form.
- **Saved servers:** every server that has been connected to (`servers.ts`) is remembered on the phone. The "Servers" section of the profile drawer lets you switch, delete or add one, and the connect screen also has a "Saved servers" list.
- **Kiosk mode is now on by default** (`settings.ts`); it can be turned off from the Settings panel.
- **Drawer lock for automatic profile switching:** client UI for the active-window-based automatic profile switching defined in the server repo `macro-grid` (see `docs/done/auto-profile-switch.md` in that repo). The new `autoSwitch: {enabled, locked}` field of the `profiles.list` message is read. If the device has opted in (`FollowActiveWindow`), a switch with a lock icon appears in the profile drawer header; tapping it pauses or resumes automatic switching through the `profile.lock` message (manual profile selection keeps working while locked). Verified end to end with real OS foreground events.
- **A failed widget action is now shown as a red toast** (for example a button bound to a deleted OBS scene): the `error`/`action_failed` envelope from the server reaches `App.tsx` through `onActionError` and draws a toast that stays for 4 s. The server side is in the `macro-grid` repo; the same pattern exists in `webclient/`. Verified end to end on a real Android phone (USB `adb install`).
- **Page navigation triggered from the client:** horizontal swipe sends `page.next`/`page.prev` (the client can now trigger the page navigation that already existed on the server).
- **Kiosk mode and orientation lock:** immersive/full screen mode with the native `KioskPlugin.java`, orientation lock with `@capacitor/screen-orientation`. A Settings panel (`SettingsPanel.tsx`) was added inside the profile drawer, and the settings persist in `localStorage`.
- **Real two-way value flow for sliders/knobs:** local `dragValues` give instant feedback while dragging (especially for Knob, which is prop-driven and has no drag state of its own), `widget.value` is sent to the server on release, and when the real `widget.state` value arrives from the server, that widget's `dragValues` entry is cleared and the server's value wins.
- Offline/last-layout cache: every `layout.full` is written to `localStorage` per host. On a cold start (when the app is reopened, not on a live reconnect), the last known grid is shown instantly even if the server is unreachable, and the badge reads "Offline · cache". Pairing always takes precedence over the cache — if a PIN is required, the connect screen is shown even when a cache exists. Verified end to end by stopping and starting the real server.
- **Pairing with a PIN:** on the first connection the 6-digit PIN shown in the server editor is requested; after pairing, the persistent token from the server is saved per host in `localStorage` and the PIN is never asked again. `ConnectScreen` now shows PIN entry in the `pairing_required` state. Verified end to end against a real server.
- Stage 5 started: a Capacitor + React + TS app (Capacitor 8.5.2). Connect screen with IP entry, a main screen that draws the same grid as `@macro/renderer`, WebSocket reconnect (exponential backoff). The `android/` platform was added, and the first `assembleDebug` build succeeded.
- `packages/renderer`: the shared grid/widget rendering engine — `Grid`, `WidgetView`, `ShadowHost`, `sanitizeWidgetCss`, `usePressGesture` (press/longPress/doubleTap/haptic).
- Profile drawer: opens with a swipe from the left edge (or an always-visible thin edge handle), lists all profiles through the `profiles.list` message from the server, and sends `profile.change` on selection to switch to the new profile immediately. Verified end to end against a real server.
- Keep the screen awake (`@capacitor-community/keep-awake`): the device does not sleep while a profile is loaded.

### Changed
- The version sent in `hello` is read from `package.json` instead of a duplicated constant. `@testing-library/dom` was added to the renderer's dev dependencies so its tests run on a fresh install.
- Documentation rewritten in English for publishing: README, `docs/architecture.md`, `docs/development.md`, `docs/versioning.md`; `CONTRIBUTING.md`, `SECURITY.md` and updated third-party notices added; the copied plan, agent notes and editor design documents were removed.

### Fixed
- **The camera preview stayed black in the QR scanner:** while scanning, the `html`/`body`/`#root` backgrounds are now made transparent, not just `body` (`QrScan.tsx`, `index.css`).
- The connection state could wrongly show "connection lost" under React 18 StrictMode: because the effect intentionally runs twice in development, the delayed `onclose` of the old (cancelled) `ServerConnection` could write "disconnected" to the state after the new connection was already open. `disconnect()` now permanently marks the connection "destroyed", and no event callback fires after that point.
- After entering the PIN and pairing, the state stayed stuck on "pairing_required" (it showed "Offline" even though data was flowing) — the `welcome` message now always moves the state to "connected".
- In `ButtonContent`, the container's `flex-direction` was changed when the icon was above/below, which swapped the axes of the `justify-content`/`align-items` set for alignment. Icon+text now sit in their own inner box (`.ms-content-inner`) — in sync with the server repo (see that repo's changelog).
